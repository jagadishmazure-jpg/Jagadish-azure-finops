# Best practices

The rules this repo follows, and that I would bring to a FinOps engagement. Each one points to
where it is implemented.

## Evidence and numbers

1. **Every number comes from a run.** Docs embed real command output and real code excerpts,
   regenerated by `scripts/render_docs.py`; CI fails if they drift (`--check`).
2. **Label estimates.** A finding that rests on an assumption (eviction rate, hit ratio, read size,
   changed fraction) carries `estimate=True` and says "(estimate)" in every report.
3. **Price from a source you can show.** List prices come from a checked-in Retail Prices
   snapshot, labelled as list prices. Negotiated prices replace it, never mix with it.
4. **Reconcile to the bill.** A saving is only credible if the "current cost" matches the FOCUS
   export for the same resources (analyzer, 5% tolerance). AI attribution reconciles to the
   model meters.
5. **Show what you skipped.** Every pattern lists skipped resources with a reason. A complete
   review is more convincing than a long list of findings.

## Order of operations

6. **Remove waste, then resize, then scale, then commit.** Idle cleanup and rightsizing come before
   autoscale; commitments and Hybrid Benefit are sized on the optimized estate (p03 and p06 read
   p01's targets).
7. **One owner pattern per resource.** Stopped VMs belong to cleanup, not rightsizing; elastic
   plans belong to autoscale. The analyzer drops duplicate changes.

## Safety

8. **Read-only by default.** The real-subscription path needs only Reader-class roles; the
   executor is dry-run only and live execution raises an error.
9. **People approve; agents propose.** Approvals are bound to a plan digest, expire after 72 hours,
   can't come from the requester, and need two people for irreversible steps and a finance role
   for purchases. The MCP server has no approve tool.
10. **Prefer reversible first.** Deallocate before delete, snapshot before delete, export config
    before deleting a plan, Audit before Deny for policies in dev.
11. **Respect explicit opt-outs.** `finops-exempt=true`, legal hold, non-interruptible jobs and
    production latency objectives are never overridden by a saving.

## Prevention

12. **Guardrails as code.** Required tags, allowed VM sizes, deny untagged public IPs, budgets with
    forecast alerts, lifecycle policies, in Terraform and Bicep from one set of policy JSON files.
13. **Smallest settings by default.** Demo resources use the cheapest SKUs; anything that bills
    while idle is opt-in (`deploy_autoscale_demo = false`).
14. **Measure tag compliance in dollars**, not resource counts.

## AI cost

15. **Attribute every request** by tenant, agent and use case, from the request log.
16. **No cost cut without an eval.** Routing, caching and model changes ship only within a quality
    budget and with zero safety regressions.
17. **Fail safe on routing.** When the classifier is unsure, use the large model.
18. **Caches are per tenant**, expire, and never answer a different entity.
19. **Budgets degrade before they block**, and never cut off a critical agent.
20. **Fund on ROI, not on spend.** Value assumptions (adoption, minutes saved) are named and
    challenged with the business owner.

## Engineering

21. **Deterministic synthetic data** with a `--check` mode, so tests and docs are reproducible.
22. **OIDC only** for CI/CD, no stored cloud secrets; deploys gated off until configured.
23. **No real identifiers** in the repo: no subscription IDs, tenant IDs, customer names or
    personal email addresses (enforced by `tests/test_repo_hygiene.py`).
24. **Pinned, scanned supply chain.** Actions pinned to commit SHAs with read-only default
    permissions, gitleaks over the full git history, CodeQL, and weekly grouped Dependabot updates
    (enforced by `tests/test_iac.py::test_workflows_are_hardened`). GitHub secret scanning, push
    protection, Dependabot alerts and a `main` ruleset are switched on in the repository settings.
